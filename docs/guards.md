# Guards

What each PreToolUse guard denies and asks. Moved from the README; the audit,
context and readability hooks are in [hooks.md](hooks.md).

A guard's deny blocks the call in every permission mode (a loaded mod is the
exception; see [known-limitations.md](known-limitations.md)). A guard's ask
comes to you even in auto mode: Claude Code's
[permission-modes doc](https://code.claude.com/docs/en/permission-modes), read
2026-10-16, says prompts forced by an ask rule or a hook are not removed by
switching to auto mode, "because auto mode still shows you those prompts". The
classifier decides only what no guard or rule names; see
[auto-mode.md](auto-mode.md). An ask costs a person's time: on one Mac,
`bin/permission-friction.py --days 23` over 2026-09-24 to 2026-10-16 (PR #90)
found an approved guard ask held its call 92 to 269 s at the median, by guard.

## What each guard does

| Hook | Event | Behaviour |
|---|---|---|
| `env-guard` | PreToolUse → Bash | Blocks commands that read, dump, copy, or exfiltrate env values or dotfiles (`cat .env`, `printenv`, `echo $API_KEY`, `cp .env /tmp/x`, `dd if=.env`, `… < .env`, `curl --data @creds`, `nc`, `eval $(env)`, etc.). A jq filter or a grep/rg pattern is text, not a file: `grep -rn '\.env' src/` is a search. So is a commit message (`git commit -F -`), a PR body (`gh … --body-file -`) or a notes file (`cat > x.md`) written by a heredoc; a heredoc fed to a shell or interpreter is still scanned, and so is one with an unquoted delimiter whose body holds `$` or a backtick, which the shell runs. A command naming none of the words it guards (a credential file, `env`/`set`/`printenv`, a secret-named variable, `curl`, `nc`, `eval`) exits in ~15 ms: 91% of 5,919 logged commands on one Mac. |
| `sensitive-file-guard` | PreToolUse → Read/Edit/Write/MultiEdit/NotebookEdit/**Grep** | Blocks access to `*.env`, `*.pem`, `*.key`, SSH keys, AWS creds, `.npmrc`, `.git-credentials`, `.pgpass`, `.kube/config`, `.ssh/config`, `.docker/config.json`, `credentials.json`, service-account JSON. Resolves symlinks so a symlinked path can't bypass. **Grep** prints file content like `Read` does, so it is guarded on the same list: its `path` is checked as a file *and* as a credentials directory (`~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.kube`, which a content search would dump wholesale), and its `glob` is checked in de-globbed form, so `*.env`, `**/.env*` and `*.{env,ts}` are all denied. Grep's `pattern` is the text being searched *for*, never a target: grepping source for `process.env.API_KEY` stays an ordinary read. |
| `git-guard` | PreToolUse → Bash | Denies force-push in every spelling (`--force`, `--force-with-lease`, a bundled short flag like `-fu`/`-qf`, a `+` refspec, `--mirror` or any prefix of it git takes, down to `--m`), `reset --hard`, `clean -f`, writes into `.git/hooks` (the directory, so `cd .git/hooks && cat > pre-commit` counts), `core.hooksPath` tampering (including via `-c`), shell-body (`!`) aliases, `filter-branch`. A broad `git add` (`.`, `./`, `:/`, `-A` or a short cluster holding it like `-vA`, `--all` or `--al`, including behind a flag like `git add -v .`) is denied only when `git status` lists a file it would stage that is on the credential list sensitive-file-guard uses too (`CREDENTIAL_FILES` in `hooks/lib.sh`, one list so the two cannot drift) (porcelain paths are repo-relative, so a subdirectory's `.` is covered); a clean broad add runs. With `-f` in any spelling git takes (`-fA`, `-vf`, `--forc`), `xargs`, a `cd` first, or a repo it cannot find, it still denies. Asks before `branch -d/-D` unless a remote-tracking ref holds every named branch's tip. Likewise `push --delete`, `push -d` and `push origin :branch` run when the remote branch's tip, read from the remote with `git ls-remote`, is held by another ref (a local branch, a tag, or a different remote-tracking ref); a branch only the remote holds, the remote's default branch, or anything it cannot check still asks. Normalizes `git -c k=v` / `-C dir` global-option prefixes, and (via `normalize_wrappers`) leading env assignments and wrapper commands, so neither can break the match. A commit-message heredoc (`git commit -F -`) is text and is not scanned, unless its delimiter is unquoted and the body holds `$` or a backtick. |
| `rm-guard` | PreToolUse → Bash | Denies recursive `rm` of `/`, `~`, `$HOME`, `.`, `..`, `*` or a top-level folder, `-f` or not, and any `rm -rf` (every spelling: `-fr`, `-r -f`, `--recursive --force`) outside this session's scratch folder. Inside `$CLAUDE_JOB_DIR/tmp`, or the sandbox's `/tmp/claude-<uid>/<job id>`, it runs: the folder comes from the hook's session id (or, for a resumed job, which runs under a new id, from the job whose `state.json` names it), a `..` or a command that sets `CLAUDE_JOB_DIR`, `HOME` or `TMPDIR` gets no allowance, and `cd` into scratch or `T=<scratch path>` earlier in the same command counts, unless the command holds a `(`: a cd inside a subshell does not last. Replaces the `Bash(rm -rf:*)` deny rules, which matched one spelling and refused the scratch folder 197 times in 49 days on one machine. |
| `config-guard` | PreToolUse → Bash/Write/Edit/MultiEdit/NotebookEdit | Asks before a write into `~/.claude/hooks` or to the scripts directly in `~/.claude` (`statusline.sh` runs outside the sandbox): `cp`/`mv`/`rm`/`ln`/`chmod`/`tee`/`sed -i`/`curl -o`/`>` from Bash, and the file tools. Denies moving or emptying `~/.claude` itself. Also asks before a write to a Claude Code settings file, a shell startup file (`~/.zshrc`, `~/.bashrc`, `~/.profile`, …), `~/.gitconfig` (including `git config --global`) or `~/Library/LaunchAgents`. Reads pass, and a write made from inside an interpreter is not seen. |
| `interpreter-guard` | PreToolUse → Bash | Asks before `python -c` / `node -e` / `ruby -e` / `perl -ne` / `php -r` / `bash -c` and heredocs when the payload references env vars, dotfiles, sockets, or an env-dumping command, including when wrapped in a command runner (`poetry run`, `env`, `timeout`, `nohup`, …). A shell-out alone (`subprocess.run`, `os.system`, `child_process`, `IO.popen`) is glue and runs; what it runs is still scanned, so `subprocess.run(['printenv'])` asks. A commit message, PR body or notes file written by a heredoc is text, unless its delimiter is unquoted and the body holds `$` or a backtick. A command naming no interpreter exits in ~15 ms. Raises the bar on the interpreter-bypass route, but string-obfuscated payloads can still evade a regex; the OS sandbox is the real containment. |
| `network-guard` | PreToolUse → Bash, WebFetch | Denies file-body uploads via `curl -d @…` / `-d@…` / `--data=@…`, `-F @…`, `-T`, **and pipe-to-shell remote code execution** (piping curl/wget into a shell or interpreter, process substitution, or command substitution). An interpreter running a local script file, or `python3 -m json.tool`, reads the download as data and is allowed. Prompts on `scp`/`rsync`/`sftp` to a remote host and on local HTTP servers. |
| `secret-scanner` | PreToolUse → Write/Edit/MultiEdit/NotebookEdit | Scans the payload before it hits disk; denies AWS keys, JWTs, PEM blocks, GitHub/Slack(token+webhook)/Stripe/Google/Anthropic/OpenAI(incl. `sk-proj-`) tokens and GCP service-account keys |
| `mod-gate` | PreToolUse → Write/Edit/MultiEdit/NotebookEdit | On a Claude Code mod's files, runs `claude plugin validate` on the mod as it will be after the write. Denies hooks that replace permission decisions (`tool.check`, `classic.PreToolUse`, `classic.PermissionRequest`, `plugin.register`, `engine.create`); otherwise tells you what the mod hooks and calls. Any other file exits in ~5 ms. See [known-limitations.md](known-limitations.md). |

## When a guard asks

| Hook | Triggers |
|---|---|
| `git-guard` | `git branch -D` of a branch whose tip no remote-tracking ref holds, or one it cannot check (a name in a variable, xargs, a `cd` first), `git push --delete` / `git push origin :branch` of a branch whose remote tip no other ref holds, or one it cannot check (not a configured remote, `ls-remote` fails or times out, the remote's default branch, a name in a variable, a `cd` first), `git remote set-url`, `git config user.email`, non-shell `git config alias.*`, glob staging (`git add '*.ts'`) |
| `interpreter-guard` | Long inline scripts with no obvious sensitive token |
| `kubectl-guard` | Every mutating `kubectl` verb (`delete`, `apply`, `patch`, `replace`, `edit`, `scale`, `drain`, `cordon`, `taint`, `exec` (except a non-interactive `exec … --` running `ls`, `id`, `df`, `hostname` and similar, or any command asked only for `--version`/`--help`; `cat`, `env`, `printenv` and `ps` still ask), `cp`, `run`, `debug`, `proxy`, `rollout undo/restart`, `auth reconcile`, `config use-context`, …) wherever the verb sits in the command, plus `get secret` in every spelling that returns the data (`secret/db-creds`, `pods,secrets`, `Secret`, `secrets.v1.`, and the `--raw /api/v1/…/secrets` path: credential materialisation), and any subcommand on neither list (fails closed). Only the resource *kind* is compared, so a CRD that merely starts with the word (`secretproviderclass`, `sealedsecrets`) stays a silent read. Exists because `kubectl` takes its global flags **before** the verb, so a prefix-matched rule like `Bash(kubectl delete:*)` misses `kubectl --namespace vm delete pod foo`: no allow/deny pair in `settings.json` can express this. That deny rule is retired in `config/retired-rules.json`, so an install removes it, and this guard asks on every spelling, the verb-first one included. Escalates rather than blocks: auto mode ships ~10 kubectl-specific `soft_deny` rules that clear when you name the target, and a hook `deny` would preempt all of them. Read-only verbs (`get`, `describe`, `logs`, `top`, `port-forward`, `rollout status`, `auth can-i`, `config view`, …) pass silently; flag *values* are skipped so `--context delete-me get pods` is still a read, a substitution among them too (`-n "$(cat ns)" get pods`). A value the command sets is put in place before the scan, so `k=kubectl; "$k" delete`, `x='kubectl delete pod x'; eval "$x"`, `${KUBECTL:-kubectl} delete` and `$(which kubectl) delete` ask while their `get` forms stay reads; a verb or `get` kind that comes from xargs's input, a substitution or a variable set elsewhere asks (`… | xargs kubectl`, `kubectl $(cat verb)`, `kubectl get "$KIND"`). See [known-limitations.md](known-limitations.md) for what stays out of reach. `kubectl` inside a PR title, a commit message or a `git stash -m` is text when every segment is a text tool, `gh`, or a git subcommand that never runs an argument (`git bisect run` and `rebase -x` still ask). A command with no `kubectl` in it exits in ~15 ms. |
| `network-guard` | `curl -X DELETE` (any host), a request body (`-X POST/PUT/PATCH`, `-d`, `--json`, `-F`, a bundled `-sXPOST` or `--request=`) to any host except this machine and hosts added with `net-allowlist.sh add --body` (a loopback body still asks for an admin API, or while a port-forward, `ssh -L`, socat, cloudflared or ngrok runs or appears in the command), `curl`/`wget`/`WebFetch` to a non-allowlisted domain. A GET to this machine (`127.x`, `localhost`, `::1`) is allowed, except a local admin API (ports 8001 `kubectl proxy`, 2375/2376 Docker, 8200 Vault, or Kubernetes API paths on any port), which asks; every URL in the command is checked, by the host curl actually connects to. Adding a host to this machine's allowlist (`net-allowlist.sh add`, or a write into `~/.claude/local-settings`) asks too; a writer counts only at the head of its segment, so `install-run.sh` named in a grep is not `install`. A commit-message or PR-body heredoc is text, unless its delimiter is unquoted and the body holds `$` or a backtick. A command naming none of `curl`, `wget`, `scp`, `rsync`, `sftp`, `http`, `php` or the allowlist exits in ~15 ms. |
| `sensitive-file-guard` | A Grep whose `path` is your home folder or above it, and a Grep `glob` with `?`, `[..]` or more than one brace group, which the credential check cannot read |
| `mod-gate` | A mod `claude plugin validate` gives no report for, and a mod that hooks `tool.call` or calls something that runs outside the guards (`$.process`, `$.http`, `$.fs.write`, …) |

## Allowlisting a wrapper script bypasses every guard

A PreToolUse hook sees only the top-level Bash command, never the `kubectl` or
`git` calls a script makes internally. `config/settings.json` ships no
`~/.claude/skills/*` allow entry, and one added in a local-settings fragment is
safest as a read-only probe: allowlisting a probe that creates and deletes
cluster resources would launder `kubectl-guard`, which would never see inside
it.
